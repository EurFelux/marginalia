# 自定义划词指令 — Design

**Issue:** #129
**Date:** 2026-10-12
**Source:** 用户请求 2026-10-12（「自定义划词 action，可设置 prompt，icon，text」）；四个取舍由用户选定：内置指令并入同一列表、每个指令单独设「直接发送」、图标用精选 lucide、超出部分收进「更多」。评审时用户补充：改用单独的表存储（§3.2）；内置指令的文字有 i18n，不能改；图标改了也没多大意义，也不让改；只有提示语可以改；「询问」也建模为内置指令，默认排第一（§3.1）。看过 UI 原型后（`prototype/selection-actions` 分支），用户选定：设置页用左右分栏、即改即存（§3.6）；工具栏合并「文字平铺」与「只显示图标」两个方案，用一个开关切换，关掉时整条工具栏只显示图标，并多平铺几个（§3.4）。界面文案：「动作」改叫「指令」；「AI 问」改名「询问」（§3.7）。之后用户补充：内置指令（含「询问」）都可改提示语，提示语留空 = 用默认（§3.1、§3.6）；图标网格太占地方，改成点按钮弹出浮层；文字框不要标题，字数放进输入框末尾（§3.6）。

## 1. 背景

选中文字后弹出的工具栏有三个固定的 AI 指令：解释、翻译、概括。点一下就把对应的提示语填进 AI 输入框，选区作为上下文附在这条消息上。提示语写死在 i18n 里，翻译的目标语言跟着界面语言走（中文界面译成简体中文，英文界面译成英文）。

读者常有自己固定的问法，比如「这个术语是什么意思」「翻译成日语」「找找反驳这段的观点」。现在只能每次点「AI 问」再手打一遍；想把翻译改成译成日语，也没有地方改。

## 2. 目标与非目标

**目标**：

- 读者可以新建划词指令，每个指令有自己的文字、图标、提示语。
- 内置的询问 / 解释 / 翻译 / 概括和自建指令放在同一个列表里，都能隐藏、调整顺序；内置指令最多只能改提示语，自建指令的文字、图标、提示语都能改。
- 每个指令可以单独设成「直接发送」：点了就带着选区发给 AI，不用再按回车。
- 指令多了工具栏放不下时，多出来的收进「更多」。
- 读者可以让工具栏只显示图标，更紧凑。

**非目标**：

- 高亮、添加笔记两个按钮不变，不进列表、不可配置。
- 提示语里不支持 `{{selection}}` 之类的变量：选区始终和现在一样，作为上下文附在消息上。
- 不支持给指令绑定快捷键。
- 不支持导入导出指令列表（它在数据库里，随整库备份走）。
- 不做 #36（工具栏迁到 Base UI Popover）。

## 3. 设计

### 3.1 列表由什么组成

一个有序列表，每项是一个指令，分两种：

- **内置指令**：询问、解释、翻译、概括，各有固定 id（`ask` / `explain` / `translate` / `summarize`），出厂按此顺序。只能隐藏，不能删除。文字（走 i18n）和图标固定。
  - **只有提示语可以改**（四个都可以）。提示语**留空 = 用默认**：解释、翻译、概括的默认提示语跟随界面语言；「询问」的默认是没有提示语。改过就固定为读者写的内容，清空即回到默认。
  - 「询问」用默认（没有提示语）时，点了只附上选区、保留输入框里的草稿，让读者自己写问题（和现在一样）。读者给它写了提示语后，它就和其他指令一样。

**实际提示语** = 读者写的提示语，没写就用默认。下文说「没有提示语」都指实际提示语为空，目前只可能是没写提示语的「询问」。

- **自建指令**：读者新建的，id 是应用侧生成的 uuid。文字、图标、提示语都必填，可以删除。

每项另有两个开关：

- **显示**：关掉后不出现在工具栏上，留在设置页的列表里。
- **直接发送**：见 §3.5。默认关。

### 3.2 数据

新建一张表 `selection_actions`，每个指令一行。不存成一条偏好：偏好是整份 JSON 一起校验，只要有一项不合当前规则，整份就被当成没存过、退回出厂列表，读者自建的指令会一次性全丢（评审时用户提出改用单独的表）。

| 列                          | 类型         | 说明                                                                                                |
| --------------------------- | ------------ | --------------------------------------------------------------------------------------------------- |
| `id`                        | text 主键    | 内置指令用固定 id（`ask` / `explain` / `translate` / `summarize`）；自建指令用 uuidv7（应用侧生成） |
| `kind`                      | text         | `builtin` / `custom`，带 CHECK                                                                      |
| `label`                     | text，可空   | 内置为空（文字走 i18n）；自建必填                                                                   |
| `icon`                      | text，可空   | 内置为空（图标固定）；自建必填                                                                      |
| `prompt`                    | text，可空   | 内置为空 = 用默认（解释 / 翻译 / 概括跟随界面语言，`ask` 没有提示语）；自建必填                     |
| `enabled`                   | integer 布尔 | 显示开关                                                                                            |
| `auto_send`                 | integer 布尔 | 直接发送                                                                                            |
| `position`                  | integer      | 排序位，从 0 起；每次拖拽排序整表重写（同书库的 `books.position`）                                  |
| `created_at` / `updated_at` | integer      | 毫秒时间戳                                                                                          |

表级 CHECK 保证两种行的形状：内置行的 `label`、`icon` 必须为空；自建行的 `label`、`icon`、`prompt` 必须非空。

**内置指令按需落行**：

- 表里没有某个内置指令的行时，读出来就是它的出厂状态（显示、不直接发送、提示语跟随语言）。全新安装时表是空的，读出来就是「询问、解释、翻译、概括」四项，和现在的工具栏一样（只是「AI 问」改名为「询问」）。
- 读取结果 = 表里的行按 `position` 排序，再把缺行的内置指令按出厂顺序补在末尾。将来新增内置指令时，老用户也会自动看到它。
- 任何写操作（新建、编辑、删除、排序）开始前，先在同一个事务里把缺行的内置指令补成行，排在现有行之后。这样第一次新建自建指令时，它会排在四个内置指令后面，而不是跑到最前。

**读取宽松，写入严格**：

- 读取时逐行校验，只看形状（`kind` 合法、自建行三个字段非空、内置行的 id 是现有的内置 id）。不合格的行跳过并记一条 warn，不删，也不影响其他行。
- 字数和数量上限只在写入时检查（IPC 入参的 Zod schema）。以后就算收紧上限，已经存下的指令也照常读出：文字过长时工具栏按宽度省略；编辑时要先改到上限以内才能保存。
- 规则常量放在 `src/shared/selection-actions.ts`，校验与设置页文案共用（文案用插值，不写死数字）：

```ts
export const SELECTION_ACTION_MAX = 20; // 最多多少个指令（含内置）
export const SELECTION_ACTION_LABEL_MAX = 16; // 文字最长多少字符
export const SELECTION_ACTION_PROMPT_MAX = 2000; // 提示语最长多少字符
export const SELECTION_ACTION_INLINE_LABELED = 4; // 显示文字时平铺几个（出厂四个内置指令正好全部平铺）
export const SELECTION_ACTION_INLINE_ICONS = 8; // 只显示图标时平铺几个
```

- 文字、提示语存前先去掉首尾空白，不能为空，长度不超过上限。图标写入时必须在 §3.3 的清单里。
- 数量满 `SELECTION_ACTION_MAX` 时拒绝新建。上限下调后已有的指令不受影响，只是不能再加。

**业务逻辑在主进程**（`src/main/selection-actions/`，纯函数注入 DB，`:memory:` 单测），经 IPC 暴露：

| 通道                       | 入参                         | 说明                                                                            |
| -------------------------- | ---------------------------- | ------------------------------------------------------------------------------- |
| `selectionActions:list`    | 无                           | 按上面的规则读出完整列表                                                        |
| `selectionActions:create`  | 文字、图标、提示语、直接发送 | 自建指令，排在末尾，默认显示                                                    |
| `selectionActions:update`  | id + 要改的字段              | 内置指令接受提示语（`null` = 用默认）、显示、直接发送；自建指令还可改文字和图标 |
| `selectionActions:delete`  | id                           | 只能删自建指令                                                                  |
| `selectionActions:reorder` | 完整的 id 顺序               | 必须正好是当前列表的一个排列，否则拒绝；`position` 按新顺序重写为 0..n-1        |

- 返回给渲染层的内置指令只带 `prompt: string | null`，文字、图标、出厂提示语由渲染层按当前界面语言解析。这样切换语言立刻生效。
- 编辑内置指令时，提示语留空或和当前语言的默认值相同，渲染层就传 `null`，不存成文字。这样只改了「直接发送」的读者，切换界面语言后提示语照样跟着变。
- 渲染层用 react-query 读取（`qk.selectionActions`），写操作成功后让它失效重取。阅读器打开时预取，工具栏弹出时不用等。
- 整库备份用 SQLite 的 `.backup()`，新表自动包含在内。

### 3.3 图标

从一份精选的 lucide 图标里选，共 48 个，按用途分组排列：

| 组         | 图标                                                                                                                                             |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 阅读与语言 | `book-open` `book-a` `languages` `spell-check` `quote` `message-square-quote` `pilcrow` `scroll-text` `file-text` `library`                      |
| 思考与提问 | `sparkles` `lightbulb` `brain` `circle-help` `message-circle-question` `search` `glasses` `microscope` `telescope` `target`                      |
| 结构与比较 | `list` `list-checks` `list-tree` `network` `route` `git-compare` `scale` `swords` `shrink` `expand`                                              |
| 学科与主题 | `graduation-cap` `baby` `history` `calendar` `globe` `map` `compass` `landmark` `users` `drama` `palette` `music` `sigma` `flask-conical` `code` |
| 其他       | `pen-line` `wand-sparkles` `heart`                                                                                                               |

- 表里存图标的 kebab-case 名字。清单（名字数组）放在 `src/shared/selection-actions.ts`，渲染层用 `Record<名字, LucideIcon>` 映射，漏配会编译报错。
- 读取时对图标只要求是非空字符串，不限定在清单内；渲染时认不出的名字退回 `sparkles`。这样将来从清单里删掉某个图标，用过它的指令照常显示。
- 内置指令的图标固定，沿用现在的：询问 `sparkles`、解释 `book-open`、翻译 `languages`、概括 `file-text`。图标选择器只出现在自建指令的编辑区里。

### 3.4 工具栏

两种样子，由设置页的「工具栏显示文字」开关切换（§3.6），默认开：

```
显示文字（默认）：
[🖍 高亮标记] [📝 添加笔记] | [✦ 询问] [📖 解释] [🌐 翻译] [📄 概括] [··· 更多]

只显示图标：
[🖍] [📝] | [✦] [📖] [🌐] [📄] [🔬] [🧠] [🇯] [🕰] [···]
```

- 只显示「显示」开着的指令，按列表顺序排。
- 显示文字时平铺前 `SELECTION_ACTION_INLINE_LABELED`（4）个，只显示图标时平铺前 `SELECTION_ACTION_INLINE_ICONS`（8）个；多出来的收进末尾的「更多」。只多出 0 个时不显示「更多」。
- 只显示图标时，**整条工具栏**都只显示图标，包括「高亮标记」「添加笔记」和「更多」；鼠标悬停时显示文字（用现有的 Tooltip）。
- 「询问」按 id 用主色（和现在一样），排在哪里、平铺还是在「更多」里都一样。
- 「更多」点开是一个小菜单，从按钮下方展开，每行一个图标加文字（两种样子相同），开着「直接发送」的行尾带一个小发送图标。菜单画在工具栏自身里，不挂到 body 上：点菜单时同样要阻止 mousedown 的默认行为，否则 PDF 里的选区会被清掉、工具栏随之消失。
- 所有指令都隐藏时，工具栏只剩「高亮标记」「添加笔记」，分隔线也不画。
- 工具栏的水平位置改为按实际宽度夹在窗口内（左右各留 8px）。现在用写死的半宽 220px 估算，指令文字变长后会出界。
- 开关存成一条偏好 `selectionToolbarLabels`（布尔，未存 = 开），在 `src/shared/preferences.ts` 注册。它只是一个布尔值，不存在上面说的整份作废的问题。

### 3.5 点击后发生什么

所有指令都和现在一样：先用选区生成上下文（`buildChips`），打开 AI 面板，收起工具栏。之后：

- **没有提示语**（只可能是没写提示语的「询问」）：选区放进草稿的上下文，**保留**输入框里已有的文字，输入框获得焦点。此时「直接发送」不起作用（没东西可发），设置里的开关也显示为禁用。

- **有提示语、「直接发送」关着**（默认，等于现在解释 / 翻译 / 概括的行为）：提示语覆盖输入框里的草稿，选区放进草稿的上下文，输入框获得焦点，光标在末尾，等读者补充或按回车。
- **有提示语、「直接发送」开着**：立即发出一条消息，内容是提示语，带着选区作为上下文。
  - **不动输入框里已有的草稿文字**：读者可能正写到一半，直接发送不该把它吞掉。
  - 和读者手动按回车走同一条发送路径，所以已打开的章节 / 全书摘要也会随这条一起发出，发出后回落为关闭（和现在手动发送时一样）。实现上由 Composer 注册一个「发送」句柄，和现有的聚焦句柄（`composer-focus.ts`）同一个模式。
  - **AI 正在回复时**发不出去，退回到「直接发送」关着的行为：提示语和选区填进输入框，等这轮回复结束后读者自己按回车。

### 3.6 设置页

设置里新增一个分类「划词」（English: Selection），放在「阅读」之后。页面从上到下：

```
划词

工具栏显示文字                                              [●]
关掉后只显示图标，鼠标悬停时显示文字。

划词指令
选中文字后，工具栏上的 AI 指令。前 4 个直接显示，其余收进「更多」。
┌──────────────────────┬──────────────────────────────────────┐
│ ⠿ ✦ 询问       [●]  │ [🔬] [找反驳                3/16]     │
│ ⠿ 📖 解释       [●]  │                                      │
│ ⠿ 🌐 翻译  ➤    [●]  │    提示语 [……]                       │
│ ⠿ 📄 概括       [●]  │    直接发送                    [○]    │
│ ── 以下收进「更多」── │                                      │
│ ⠿ 🔬 找反驳     [●]◀ │ 改动会自动保存          [🗑 删除指令] │
│ ⠿ 🧠 术语  ➤    [○]  │                                      │
│ [+ 添加指令]          │                                      │
└──────────────────────┴──────────────────────────────────────┘
```

**左栏：列表**

- 每行：拖拽手柄、图标、文字、「直接发送」小图标（开着时才显示）、显示开关。点行选中，右栏显示它的编辑区；打开页面时默认选中第一行。
- 隐藏的指令整行变淡。
- 拖拽排序用 dnd-kit（书库网格已在用），支持键盘排序。
- 在第 n 个显示中的指令之后画一条分隔线，标出「以下收进『更多』」，n 跟随当前的「显示文字」开关（4 或 8）。隐藏的指令不计数。节说明里的数字同样跟着变。
- 底部「添加指令」。列表满 `SELECTION_ACTION_MAX` 项时禁用，旁边说明上限（插值，不写死数字）。
- 列表过长时左栏自己滚动。

**右栏：编辑区，改动自动保存，没有保存按钮**

- 自建指令：图标和文字一行，下面是提示语（多行）、直接发送（开关）。底部「删除指令」，删除前确认。
  - 图标：文字框左边一个按钮，显示当前图标。点一下弹出浮层（Popover），里面是 §3.3 的分组网格；点选后浮层收起、立即保存。网格不常驻页面，省地方。
  - 文字：单行输入框，不加标题（和图标按钮并排，一看就知道是它的名字），占位文字「比如：找反驳」。字数 / 上限显示在输入框内的末尾。
- 内置指令：顶部只读显示图标和文字，下面只有提示语和直接发送。
  - 提示语框留空即用默认：空着时用浅色占位文字显示默认提示语，下方说明「留空则使用默认提示语。」。没有单独的「恢复默认」按钮，清空就是恢复。
  - 「询问」的占位文字是「留空：只附上选中的文字，由你自己提问」；它没写提示语时，直接发送开关禁用。
- 提示语下方说明：「选中的文字会作为上下文附在消息上，提示语里不用再写。」直接发送下方说明：「点了就发给 AI，不再填进输入框等你补充。」
- **直接发送只在实际提示语不为空时可开**（自建指令的提示语框空着，或「询问」没写提示语）。不可开时：
  - 开关禁用并显示为关（表里存的值不动，写回提示语后恢复原样）。
  - 标题变淡；整个标题区的鼠标样式是「不可用」（`cursor-not-allowed`），不是可点的手形。
  - 说明换成引导：「要先写提示语才能开启：没有提示语，就没有可以直接发出去的内容。」，不变淡，保证读得清。
  - 写下提示语的那一刻，开关立即变为可用，说明换回原文。

**自动保存的规则**

- 开关、图标：点了立即保存。
- 文字、提示语：停止输入 500ms 后保存，失去焦点时也立即保存。
- 内置指令的提示语清空是合规的（= 用默认），照常保存为 `null`。
- 内容不合规（自建指令的文字或提示语去掉首尾空白后为空，或超过上限）时不保存：输入框标红，下方提示原因（「文字不能为空」「提示语不能为空」，超长由字数显示提醒）；表里仍是上一次合规的值。离开这一项（选中别的行、关掉设置）后，输入框回到已保存的值。
- 编辑区底部一行小字「改动会自动保存」。

**新建**

- 点「添加指令」：左栏末尾出现一行「未命名」草稿并选中，右栏是空白的编辑区，焦点在文字框。
- 草稿只在页面里，**不写入表**；文字和提示语都填好（合规）的那一刻才新建（`selectionActions:create`），之后的改动照常自动保存。
- 草稿没填好就离开（选中别的行、关掉设置），草稿直接丢弃，不提示。
- 草稿也占列表数量：已满 `SELECTION_ACTION_MAX` 项时不能再加草稿。

### 3.7 文案

- `src/main/selection-actions/repository.test.ts`（`:memory:` DB）：

  - 删除：内置指令拒绝；自建指令删掉后其余顺序不变。
  - 排序：不是当前列表的排列时拒绝（缺 id、多 id、重复 id）；`position` 重写为 0..n-1。
