# 统计页的 AI 用量 — Design

**Issue:** #127
**Date:** 2026-10-12
**Source:** 用户请求 2026-10-11（「还有个 follow up 是在统计页面添加 usage 统计」）；数据来源选「新建用量账本」、后台调用「计入，按用途分开」；线框稿评审通过（页面结构选 A 标签页；「全部」按月汇总；删掉的书并成一行；回填只含对话）。
**前置:** `2026-10-11-message-usage-display-design.md`（单条消息的用量卡与 `metadata.usage`）

## 1. 背景

每条助手消息已经能显示本轮用量，但没有汇总视图，看不出一段时间里花了多少、缓存省了多少、花在哪里。

消息表不适合直接拿来做统计：重发、编辑、重新生成会删掉这一轮之后的消息，删除会话会把消息一起删掉，这些已经花掉的 token 会从统计里消失。摘要、会话命名、上下文压缩、记忆整理、阅读报告这些后台调用的用量，也从来不进消息表。

## 2. 目标与非目标

**目标**：

- 新建一张只追加、不随会话或消息删除而变化的用量账本，所有 AI 调用都记进去，并标明用途。
- 统计页加「AI 用量」标签，按时间范围显示总量、缓存命中率、请求次数、用量走势，以及按用途、按模型、按书的分布。

**非目标**：

- 不折算费用。
- 不记录 provider 设置里的连通性测试（`secrets/ai-sdk-tester.ts`）。
- 不给书库 AI 加查询用量的工具。
- 不提供清空用量统计的入口。

## 3. 界面

### 3.1 页面结构

统计页顶部加两个标签「阅读 / AI 用量」（用现有 `Tabs` 组件），默认停在「阅读」，切换不记忆。「阅读」标签下的内容和现在完全一样，包括没读过书时的空状态。「AI 用量」标签下的内容见下文，自上而下排列，沿用统计页现有的卡片样式。

### 3.2 时间范围

标签下方一个分段控件：近 7 天 / 近 30 天（默认）/ 全部。它对下面所有部分都生效。「近 N 天」包含今天，按本地日期计。

### 3.3 概览

三个数字卡片：

| 卡片       | 大字                                                     | 小字                                                       |
| ---------- | -------------------------------------------------------- | ---------------------------------------------------------- |
| 总用量     | 输入 + 输出                                              | 「输入 X · 输出 Y」                                        |
| 缓存命中率 | 缓存命中 ÷ 输入，只用报了缓存命中数的记录计算（见 §4.5） | 「X 来自缓存」                                             |
| AI 调用    | 模型请求次数                                             | 近 N 天显示「日均 X 次」；「全部」显示「含回填的历史对话」 |

范围内没有任何报了缓存命中数的记录时，缓存命中率显示「—」。

### 3.4 用量图

- 近 7 天、近 30 天按天画柱；「全部」按月画柱，从最早一条记录所在的月份画到本月。
- 每根柱子自下而上叠三段：缓存命中 / 其余输入 / 输出，颜色沿用用量卡的前景色深浅。图上方有图例。
- 悬停或键盘聚焦某根柱子，弹出这一天（或这一月）的三项数字、合计和请求次数。
- 没有用量的日子画一条贴底的细线占位。
- 纵轴刻度取整，标签用 k / M / B。

### 3.5 按用途

六行，按用量从大到小排，每行一条横向比例条，后面跟用量和占比。没有用量的用途不显示。占比四舍五入为 0% 但确有用量时写「<1%」（按书同理）。

| 用途       | 来源                          |
| ---------- | ----------------------------- |
| 对话       | AI 面板与书库 AI 的对话回复   |
| 摘要       | 章节摘要、全书摘要            |
| 阅读报告   | 写报告的 agent 及其调查子任务 |
| 上下文压缩 | 长对话折叠旧轮次              |
| 记忆整理   | 对话后的记忆整理              |
| 会话命名   | 首轮后自动起标题              |

### 3.6 按模型

表格，按输入加输出从大到小排：模型、输入、输出、缓存命中率（计算方式同 §3.3，没有可算的数据时显示「—」）、调用次数。

### 3.7 按书

- 按用量从大到小，列出前 10 本书，标题下面带作者。
- 不属于某本书的用量（书库 AI 的对话，以及由这些对话触发的后台任务）单独一行「不属于某本书」。
- 已删除的书并成一行「已删除的书」，副标题写「N 本」。
- 第 10 本之后的书并成一行「其余 N 本」。
- 后三种汇总行的名字用弱前景色，并排在所有书之后。
- 删掉后又重新导入的书，书 ID 不变（由书的标识符或文件内容决定），用量会重新归回这本书名下。

### 3.8 空状态

- 账本里还没有任何记录时，整个标签只显示一句：「和 AI 对话或生成摘要后，这里会出现用量统计。」
- 账本有记录、但所选范围内没有时，照常显示各部分：数字为 0，用量图只有占位线，分布列表显示「这段时间没有 AI 用量」。

### 3.9 数字

一律用 `formatTokens`（k / M / B，见前置 spec），请求次数和天数用普通千分位。

## 4. 数据

### 4.1 账本表

新表 `ai_usage`，一次模型请求一行（回填的旧数据是一轮一行，见 §4.4）：

| 列                                                                                  | 类型          | 说明                                                                                |
| ----------------------------------------------------------------------------------- | ------------- | ----------------------------------------------------------------------------------- |
| `id`                                                                                | text PK       | uuidv7                                                                              |
| `created_at`                                                                        | integer       | 请求完成时刻（ms）                                                                  |
| `purpose`                                                                           | text          | `chat` / `summary` / `report` / `compaction` / `memory` / `naming`，带 `CHECK` 约束 |
| `model`                                                                             | text，可空    | 模型 ID；回填时消息没记模型则为空                                                   |
| `book_id`                                                                           | text，可空    | 所属的书；**不设外键**（见下）                                                      |
| `requests`                                                                          | integer       | 这一行代表的模型请求次数；实时记录恒为 1                                            |
| `input_tokens` / `output_tokens`                                                    | integer       | 非负整数                                                                            |
| `cache_read_tokens` / `cache_write_tokens` / `no_cache_tokens` / `reasoning_tokens` | integer，可空 | provider 没报就是空，不写 0                                                         |

- `book_id` 不设外键，是为了区分两种情况：为空表示不属于某本书；有值但 `books` 里查不到，表示书已删除。阅读时长表在删书时把书 ID 置空，这里不能照搬，置空后就和「不属于某本书」混在一起了。
- `created_at` 建索引，供按时间范围筛选。
- 迁移用 `pnpm db:generate` 生成。

### 4.2 记录：计量中间件

在 SDK 的模型层记账，不改各调用点的结束、出错、中止逻辑：

- 新函数 `meteredModel(resolved, { db, purpose, bookId })`：用 `wrapLanguageModel` 给模型套一层中间件，返回包好的模型。各调用点把 `model: resolved.model` 换成它即可。
- 中间件的 `wrapGenerate` 在请求返回后取结果里的 `usage`；`wrapStream` 在流中读到 `finish` 分片时取其中的 `usage`。拿到就写一行账本。
- 请求失败、或流在 `finish` 之前被中止，这次请求没有用量，不记。这和用量卡「未完成的一步不计」的口径一致。
- provider 原始用量到账本列的换算（包括丢弃负数等非法值）复用用量卡的规则，见前置 spec §4.2。总输入或总输出拿不到时整行不记，并留一条 warn。
- 写账本失败只记 warn，不影响 AI 调用本身。

### 4.3 各调用点

| 调用点                                                              | 用途         | 书           |
| ------------------------------------------------------------------- | ------------ | ------------ |
| `ai/stream-assistant.ts`（对话回复）                                | `chat`       | 会话所属的书 |
| `ai/summary.ts`（章节摘要、全书摘要）                               | `summary`    | 这本书       |
| `reading-report/agent.ts`、`reading-report/investigation-runner.ts` | `report`     | 这本书       |
| `ai/context-compaction.ts`                                          | `compaction` | 会话所属的书 |
| `ai/memory-consolidation.ts`                                        | `memory`     | 会话所属的书 |
| `chat/conversation-title.ts`                                        | `naming`     | 会话所属的书 |

后台任务都由某个会话触发，就归到这个会话所属的书；书库 AI 的会话没有书，记为空。

### 4.4 回填

- 首次启动新版本时，在数据库初始化之后同步执行一次：把每条带 `metadata.usage` 的助手消息写成一行账本。
  - `purpose = chat`，`book_id` 取会话的书，`model` 取 `metadata.model`。
  - `created_at` 取消息时刻，`requests` 取 `stepCount`，没有则记 1。
  - 拆分字段有就带上。
- 回填和完成标记（`app_meta` 新键 `usageLedgerBackfilled`）在同一个事务里写，中途失败不会半填，下次启动重来。做法同示例书导入的 `sampleSeeded`。
- 从备份还原到没有账本的旧库后，重启时标记不存在，会再回填一次。
- 回填补不回来的：后台调用的历史，以及已被删除的消息。

### 4.5 聚合

- 纯函数接收账本行和注入的当前时刻（`Temporal.ZonedDateTime`），按本地日期分桶（「全部」按本地月份），输出 §3 各部分需要的数据。读系统时钟、读时区留在胶水层（CLAUDE.md 日期时间规范）。
- **缓存命中率的分母只算报了缓存命中数的行**：回填的旧消息、不报缓存的 provider，缓存命中数是未知而不是 0，算进分母会把命中率压低。用量图里，这些行的输入全部画在「其余输入」段。
- 按书时，用 `books` 表补标题和作者，查不到的归「已删除的书」。
- 新 IPC 通道 `stats:usage`，入参 `{ range: "7d" | "30d" | "all" }`，出参的 Zod schema 放在 `src/shared/stats.ts`。

## 5. 影响范围

- `src/main/db/schema.ts` 加表并生成迁移；`app-meta/repository.ts` 加键 `usageLedgerBackfilled`。
- 新模块 `src/main/usage/`：账本写入、计量中间件、回填、聚合纯函数。
- 用量换算：把 `ai/usage.ts` 中单个数值的校验抽出来，供逐步汇总（消息）和单次请求（账本）共用。
- §4.3 的八处调用点（`summary.ts` 里有两处）改用 `meteredModel`。阅读报告的两处共用 `reading-report/service.ts` 里同一个模型，在那里包一次即可同时覆盖。
- 启动流程：在 `initDb` 之后调用回填。
- IPC：`src/shared/stats.ts`、`src/shared/ipc.ts`、`stats-handlers.ts`、`preload.ts`。
- 渲染层：`StatsView.tsx` 加标签；新组件放在 `src/renderer/stats/usage/`。
- 文案（zh-CN / en）。

## 6. 测试

- 中间件：用 `MockLanguageModelV4` 分别走 generate 和 stream，断言各写一行、各列取值正确；provider 不报的项为空；流在 `finish` 前中止时不写；写库抛错不影响调用结果。
- 各调用点：至少覆盖对话（多步回合写多行、`book_id` 正确）和一个后台任务（用途与书正确）。
- 回填：带拆分的、只有总数的、没有 `usage` 的消息各一条，断言写入的行；执行第二次不重复；书库会话的 `book_id` 为空。
- 聚合：按天与按月分桶，跨日、跨月边界用显式时区构造；缓存命中率的分母排除未知行；按书的四种汇总行（不属于某本书、已删除、其余 N 本）；空范围的输出。
- 手测：在开发版里切换三种范围，悬停用量图；删一本书后确认它并入「已删除的书」。
