# bash 终端块默认收成一行 — Design

**Issue:** #126
**Date:** 2026-10-03
**Source:** 用户请求 2026-10-03（「ai 助手可能会给很长的命令，所以几乎会把屏幕占满」「很多时候用户压根不关心命令和输出」「希望命令截断到一行，输出默认折叠（完全不展示），按需展开」）
**前置:** `2026-10-03-bash-skills-permissions-design.md` §5.4、§6.4（本文取代 §6.4 中关于命令与输出如何显示的几条，其余不变）

## 1. 背景

现在每条 bash 调用渲染成一个终端块：命令完整显示、自动换行、不截断；输出显示最后 4 行；底部还有一行小字（耗时、输出已截断、自动批准来源）。模型常写很长的命令（管道、heredoc），一轮回复里几次调用就能占满对话面板，而用户多数时候并不看命令和输出。

## 2. 目标与非目标

**目标**：终端块默认只占一行；用户想看时点一下展开。

**非目标**：

- 不改审批操作栏（§5.4）的外观和行为。
- 不记住每个块的展开状态（重新挂载即回到收起）。
- 不改其他工具的灰色单行步骤。

## 3. 设计

### 3.1 收起（默认）

块只剩一行：

```
$ 命令原文（单行，超出部分省略号）            [徽标] ▸
```

- 命令里的换行折成空格显示在这一行里（heredoc、多行脚本也只占一行）。
- 徽标照旧（等待批准、运行中、✓ 0、✗ 退出码、已拒绝……），命令流式生成时仍不显示徽标。
- 输出、拒绝说明（`# 你拒绝了：…`）、错误信息、底部小字一律不显示——徽标已经说明了结果。

### 3.2 展开

整行是一个按钮，点击切换展开 / 收起，箭头随之转向。展开后依次显示：

1. 完整命令：自动换行、不截断（即原 §6.4 的样子）。
2. 输出（stdout 后接 stderr）：**全部**显示，限高滚动；展开时滚到末尾，因为结果、报错多在最后几行。不再有「还有 N 行，展开」这一层。
3. 拒绝说明、错误信息（若有）。
4. 底部小字：耗时、输出已截断、自动批准来源（若有）。

### 3.3 等待批准时

批准前用户必须能看清完整命令，所以**有挂起的审批请求时，命令强制完整显示**，不受收起状态影响，也不显示展开箭头（此时也没有输出可看）。用户批准或拒绝后，块回到收起状态（若用户之前没展开过）。

## 4. 影响范围

- `src/renderer/ai/BashBlock.tsx`：按 §3 改布局。
- `src/renderer/ai/bash-view.ts`：删掉 `tailLines`（及其测试）——展开即显示全部，不再需要尾部截取。
- 文案：删 `ai.bash.moreLines`；新增展开 / 收起按钮的无障碍标签。
