# 设计：i18n 系统（多语言 UI + 主进程错误消息）

> 状态：已批准设计，待写实现计划（plans/）。
> 日期：2026-06-03

## 目标

为 Marginalia 建立完整 i18n 系统：渲染层 UI 全量文案可切换语言（首批 **简体中文 / 英文**），用户偏好持久化、首启跟随系统语言；**主进程自产的错误消息**也本地化。暂不实现 RTL 语言，但把数据与 CSS 都做到 **RTL-ready**——将来加一门 RTL 语言只需新增 locale + 翻转 `dir`，无需返工。

## 范围与现状（探查结论）

- **依赖**：`package.json` 仅含 `i18next ^26.3.0` 核心，**缺 `react-i18next`**（需新增，对齐原型用的 `^17`）；新增开发工具 **`i18next-cli`（devDependency，无 peer i18next 约束）** 做抽取 + 类型生成 + lint。
- **空占位**：`src/renderer/feature/i18n/` 是空目录；`feature/` 这层在既往开发中从未用上 → 本里程碑**删除** `src/renderer/feature/`，i18n 放渲染层顶层 `src/renderer/i18n/`。
- **现成参考**：UP1 原型 `packages/ui-prototype/src/i18n.ts` 有完整 i18next 设置（`react-i18next` + 内联 TS locales + 嵌套 key 按 feature 组织 + `LANGS`/`changeLanguage` + `LanguageSwitcher`）。约定原型先行再移植，本设计移植并扩展该模式。
- **偏好持久化**：现成 `preferences` 系统——`@shared/preferences.ts` 的 `PREFERENCE_SCHEMAS` 注册表 + `setPreferenceInput` 判别联合 + `preferences-handlers.ts` switch + preload 同步快照 `window.api.preferences.getAll()` + `persistPreference`。语言偏好走与 `colorMode` **完全相同**的路径，首帧同步取到、无闪烁。
- **主进程**：当前**无菜单**（无 `Menu.`/`setApplicationMenu` 代码）→ 无菜单本地化需求。主进程参与点仅两处：暴露 `app.getLocale()`、本地化自产错误消息。
- **ROADMAP**：i18n 标 🔴；本里程碑顺带兑现 `ma5-deferred #6`（结构化 `reason` → i18n）。

## 决策记录（来自 brainstorm）

| 决策点       | 选择                                                                                                            |
| ------------ | --------------------------------------------------------------------------------------------------------------- |
| 首批语言     | **简体中文 `zh-CN`（源）+ 英文 `en`**（皆 LTR）                                                                 |
| 首启默认语言 | **跟随系统**：主进程 `app.getLocale()` → 匹配支持语言，回退 `zh-CN`                                             |
| 文案抽取范围 | **基建 + 全量抽取**：现渲染层所有硬编码中文一次性抽进 locales                                                   |
| 主进程 i18n  | **需要**：自产错误消息本地化（vanilla i18next，语言随偏好同步）                                                 |
| RTL          | 不实现 RTL 语言，但 **dir 接线 + 物理 Tailwind 工具类全量迁逻辑类** 一并做（RTL-ready）                         |
| 类型安全 key | **是**：由 `i18next-cli types` 生成的 d.ts 提供（`t("bad.key")` 编译期报错）                                    |
| 资源格式     | 内联 TS 模块（`outputFormat:'ts'` + `mergeNamespaces:true`，单文件/语言），**由 i18next-cli extract 生成/同步** |
| 开发工具     | **`i18next-cli`**：`extract`（扫 `t()` 同步键）/ `types`（生成类型）/ `lint`（揪硬编码串）/ `status`（完成度）  |
| locales 存放 | **`@shared/i18n/locales/`**（主进程也要 i18n → 两进程共享同一份资源）                                           |

## 架构：模块布局

> 厚主进程 / 薄渲染层规则下，i18n 是横切关切：**纯逻辑 + 资源在 `@shared`**，两进程各自薄 init（renderer 用 react-i18next，main 用 vanilla i18next）。

```
src/shared/i18n/
  index.ts          UILanguage = z.enum(["zh-CN","en"]); type UILanguage
                    LANGS: { code: UILanguage; label: string; dir: "ltr"|"rtl" }[]
                    matchSystemLanguage(locale: string): UILanguage
                    resolveInitialLanguage(stored: UILanguage|undefined, systemLocale: string): UILanguage
                    resources（{ "zh-CN": { translation: zhCN }, en: { translation: en } }，两进程 init 共用）
  locales/zh-CN.ts  全部文案（源/简体中文），含 errors.* 子树；export default {...} as const
  locales/en.ts     英译；export default {...} as const（键与源对齐由 i18next-cli extract 维护）
  i18next.d.ts      i18next-cli `types` 生成的类型定义（让 t() 按 key 校验；替代手写 en: typeof zhCN）

src/main/i18n.ts    vanilla i18next 实例（从 @shared/i18n resources init）
                    initMainI18n(language)、setMainLanguage(language)、t（已类型化）

src/renderer/i18n/
  index.ts          react-i18next 同步 init（从 @shared/i18n resources）；设 <html lang/dir>；
                    changeUiLanguage(code)（changeLanguage + persistPreference + 重设 dir）
  LanguageSwitcher.tsx  语言切换器（移植原型；放设置「外观」节）
```

要点：

- **类型增强放 `@shared`**：`i18next.d.ts`（i18next-cli `types` 生成，输出到 `@shared/i18n/`）据**主语言 zh-CN** 推 key 类型，无「shared → renderer」反向 import。单一 `tsconfig` 下该 ambient 增强同时让**主进程与渲染层**的 `t` 都按 key 校验。
- **单一 `translation` 命名空间**：UI 文案与 `errors.*` 同树。主进程运行时只引用 `errors.*` 键（约定），渲染层引用全部。
- 删除空目录 `src/renderer/feature/`。

## `@shared/i18n` 纯逻辑

- `UILanguage = z.enum(["zh-CN", "en"])`（被 `@shared/preferences` 复用注册偏好）。
- `LANGS = [{ code: "zh-CN", label: "中文", dir: "ltr" }, { code: "en", label: "English", dir: "ltr" }]`（`label` 用本族名，不翻译）。
- `matchSystemLanguage(locale)`：`locale` 以 `zh` 起（`zh` / `zh-CN` / `zh-TW` / `zh-HK`）→ `"zh-CN"`（当前只发简体；将来加繁体再细分），否则 → `"en"`。
- `resolveInitialLanguage(stored, systemLocale)`：`stored ?? matchSystemLanguage(systemLocale)`。

## 语言偏好 + 跟随系统

- **注册偏好**：`@shared/preferences.ts` 把 `language`（= `UILanguage`）加入 `PREFERENCE_SCHEMAS`，并在 `setPreferenceInput` 判别联合补一条 arm。
- **暴露系统 locale**：preload 同步暴露 `app.getLocale()`（与现有 `app.getVersion()` 并列，只读原始字符串；映射逻辑在 `@shared` 纯函数里可测）。
- **渲染层首帧**：i18n init 用 `lng = resolveInitialLanguage(snapshot.language, window.api.app.locale)`（`snapshot` = 同步偏好快照）→ 首屏即正确语言，无闪烁（与 theme-store 读 `colorMode` 同模式）。
- **切换**：`changeUiLanguage(code)` = `i18n.changeLanguage(code)` + `persistPreference({ key:"language", value:code })` + 重设 `<html dir>`。

## 主进程 i18n（错误消息）

- `src/main/i18n.ts`：vanilla i18next（不依赖 react），从 `@shared/i18n` 的 `resources` init；启动时（DB 就绪后）`initMainI18n(resolveInitialLanguage(storedLanguage, app.getLocale()))`。
- **改造自产错误**：主进程**自己生成**的错误消息（当前硬编码中英文）换成 `t("errors.xxx", { ...params })`。例：
  - `errors.builtinTypeOutsideCompat`（"内置 provider 的类型只能在兼容 API 内切换"）
  - `errors.builtinLabelLocked` / `errors.builtinBaseUrlLocked` / `errors.builtinUndeletable`
  - `errors.baseUrlRequiredCustom`（"baseUrl is required for custom (non-builtin) providers"）
  - `errors.providerNotFound` / `errors.noApiKey` / `errors.keyUndecryptable` / `errors.secureStorageUnavailable`
  - assistant 解析的 `reason.*`（兑现 ma5-deferred #6）
- **honest-error 透传不动**：从 provider API 抓到的原文（`mapModelsError` / tester 的 provider message）**不**经 i18n——那不是我们的字符串，本地化它会篡改真相（违反 honest-error 原则）。
- **语言同步**：`preferences-handlers.ts` 的 `language` arm 在落盘后调 `setMainLanguage(value)`，使后续错误跟随当前 UI 语言。

## RTL 预留：dir 接线 + 物理工具类全量迁移

- **dir 接线**：i18n init 与每次切换时，在 **renderer 入口**（非 preload——preload 顶层 `document.documentElement` 为 null，碰 DOM 崩整个 preload）设 `document.documentElement.lang` 与 `dir`（取 `LANGS[code].dir`，今恒 `"ltr"`）。加 RTL 语言＝新增一条 `dir:"rtl"` 的 LANGS + 其 locale，`dir` 自动翻转。
- **物理 → 逻辑工具类全量迁移**（本里程碑内）：现有 Tailwind 物理方向类按下表迁为逻辑类。**LTR 下渲染零变化**（逻辑类在 LTR ≡ 物理类）→ 视觉安全、对当前 zh-CN/en 无回归。

  | 物理                                                | 逻辑                                                |
  | --------------------------------------------------- | --------------------------------------------------- |
  | `pl-* / pr-*`                                       | `ps-* / pe-*`                                       |
  | `ml-* / mr-*`                                       | `ms-* / me-*`                                       |
  | `left-* / right-*`                                  | `start-* / end-*`                                   |
  | `text-left / text-right`                            | `text-start / text-end`                             |
  | `rounded-l-* / rounded-r-*`（及 `-tl/-tr/-bl/-br`） | `rounded-s-* / rounded-e-*`（及 `-ss/-se/-es/-ee`） |
  | `border-l / border-r`                               | `border-s / border-e`                               |

  **判断保留项**：纯对称用法（如浮层居中 `left-1/2 -translate-x-1/2`）方向无关，可保留或迁移皆可，逐文件按语义判断；真正方向性的（如右对齐的浮层 `right-0`）必须迁。计划按区逐文件扫，typecheck/既有测试 + 人工 GUI 守护。

## 开发工具：i18next-cli（抽取 / 类型 / lint）

- **配置**：根 `i18next.config.ts`，关键字段：`locales: ["zh-CN","en"]`、`extract.primaryLanguage: "zh-CN"`（源）、`extract.input: ["src/**/*.{ts,tsx}"]`（含主进程，统一收键）、`extract.output: "src/shared/i18n/locales/{{language}}.ts"`、`extract.outputFormat: "ts"`、`extract.mergeNamespaces: true`、`extract.defaultValue`（en 缺译填 `""` 或 `TODO:` 标记）、`types.input: ["src/shared/i18n/locales/zh-CN.ts"]` → `types.output: "src/shared/i18n/i18next.d.ts"`。
- **package.json 脚本**：`i18n:extract`（`i18next extract --sync-primary`，扫码同步键、用代码默认值回填 zh-CN）、`i18n:types`（生成类型 d.ts）、`i18n:lint`（揪未抽取的硬编码 user-facing 串）、`i18n:status`（翻译完成度）。`extract --with-types` 可一步出键+类型。
- **可选守护**：CI / pre-commit 跑 `i18next extract --ci`（键与代码不同步则失败），防漏抽。

## 全量文案抽取 + 类型安全 key

- **半自动工作流**：逐组件把硬编码中文换 `t("ns.key", "中文源文", { ...interp })`（第二参=源默认值）→ 跑 `pnpm i18n:extract` → i18next-cli 以 `primaryLanguage: zh-CN` 把中文写进 `zh-CN.ts`、`en.ts` 留空待译 → 人工补 en 英译 → `pnpm i18n:types` 重生类型。`i18n:lint` 辅助定位还没换的硬编码串。
- **命名空间**（嵌套 key 按 feature 组织）：`common`（save/cancel/delete/edit/close…）、`nav`、`lang`、`settings`（含 models/appearance/reading + provider form/card）、`library`、`reader`、`ai`、`errors`。完整 key 树由 extract 自动生成，无需手列。
- **不走 i18n 的内容文本**：书正文、AI 回复流、用户填的 provider/模型名等**数据**——只本地化 UI 外壳文案（`i18n:lint` 的 `ignoredTags`/属性可白名单这些动态内容节点）。
- **类型安全 key**：`i18next-cli types` 据主语言 zh-CN 生成 d.ts，`t("a.b")` 写错/漏 key 编译期报错；**键对齐**由 `extract` 保证两文件同键；**缺译**（en 空串）由 `i18n:status` 暴露（非类型错误）。

## 测试

- **shared 纯函数**：`matchSystemLanguage`（各档系统 locale）、`resolveInitialLanguage`（stored 优先 / 回退）。
- **`language` 偏好往返**：复用 preferences 测试模式。
- **主进程 i18n**：`t("errors.x")` 在 `setMainLanguage("zh-CN")` 与 `"en"` 下返回对应文案；`changeLanguage` 后即时生效。
- **key 对齐**：由 i18next-cli（`extract` 同步键 + `types` 类型校验）保证，无需运行时 parity 测试。
- 文案抽取与 CSS 迁移本身无新逻辑（presentational）→ 靠 `pnpm typecheck` + `i18n:lint`/`i18n:status` + 既有测试 + 人工 GUI smoke 守护。

## 范围外 / 推迟

- **RTL 语言本身**（阿拉伯语/希伯来语等）：不加；仅做到 RTL-ready。
- **菜单 / 系统托盘本地化**：当前无菜单，不涉及。
- **复数 / 日期 / 数字格式化**（ICU 复杂规则）：当前文案无复杂复数需求，用 i18next 基础插值 `{{var}}` 即可；将来需要再引 `Intl`/插件。
- **按需懒加载 locale**：两门语言资源极小，同步内联即可，不做 HTTP/动态 import 后端。

## 实施切片（供 plan 参考）

里程碑较大，plan 按下列区切成多组 bite-sized task，建议顺序：

1. **基建 + 工具**：依赖（`react-i18next` + `i18next-cli`）、`i18next.config.ts` + `i18n:*` 脚本、`@shared/i18n`（枚举/LANGS/映射/resources/locales 骨架/生成类型）、`language` 偏好注册、preload 暴露 `app.getLocale()`。
2. **主进程 i18n**：`src/main/i18n.ts` + 错误消息改造 + 偏好语言同步。
3. **渲染层基建**：`src/renderer/i18n/` init + dir 接线 + `LanguageSwitcher` + 接入设置「外观」节 + 删 `feature/`。
4. **文案抽取**：按区 settings → library → reader → ai 逐组件抽取。
5. **CSS 迁移**：物理 → 逻辑工具类逐文件扫。
